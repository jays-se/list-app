## Decisions

| Decision | Why | Recorded in |
|---|---|---|
| Bulk create is all-or-nothing, and failures name the line (`titles[i]`) | The reference AC says "a bulk failure is atomic"; the user can fix one line and resubmit | ADR-0024 |
| The idempotency key is the batch id plus a hash of the content, and the response is stored as text | A retry replays identical bytes; an edited submit gets a new key instead of a 422 | ADR-0024, SCHEMA_DOC |
| PERSONAL captures are assigned to the creator | "Personal" means mine; meeting notes are for the team to triage | ADR-0024 |
| Member cleanup runs in `tasksvc.RemoveMemberTx`, injected into the workspace service | One transaction, with no import cycle between modules | ADR-0024 |
| The worker resets when a 409 `no_active_workspace` shows the **active workspace changed**, instead of using a time throttle | The first version (a 5 s throttle) was defeated by an earlier harmless 409 during onboarding, which e2e caught; comparing session state can't loop and doesn't depend on timing | `create-kernel.ts` |
| The dashboard and calendar are computed in the worker from the existing task list | No new endpoint; add one only past about 10k tasks | ADR-0024 |
| The home page is the dashboard; the API status card moves to its bottom | Keeps the Sprint 0 probe, and the smoke test still covers it | DashboardPage |
