## Decisions made during implementation (the requester can override)

| Decision | Why | Recorded in |
|---|---|---|
| Use `coreos/go-oidc` + `x/oauth2` instead of hand-rolled ID-token checks | Verifying ID tokens is security-critical | ADR-0017 |
| Built-in **dev identity provider** in dev/test only; config refuses it in prod | Local work and e2e need no Google credentials; no Docker is required for a fake OIDC server | ADR-0017 |
| Users identified by `(provider, subject)`; email no longer unique | Standard OIDC practice | migration 0002, SCHEMA_DOC |
| In-house OpenAPI → TS types and strict decoders, with `yaml` as a dev-only parser; Go structs stay hand-written | Minimal dependencies; drift is caught by tests | ADR-0018 |
| `VALIDATION` error code, `ctx.resetData()`, `skipAuthRedirect` | Clean handling of validation, tenant changes and the expected 401 | ADR-0019 |
| E3-S5 (settings: invite code and members) pulled in from S5 | Needed so a second person can join | backlog |
| After sign-out, the guard sends you to `/login?returnTo=<page>` | One redirect path, so no race; signing back in returns you to the same page | E3-S2 |
| The first sign-in of a new session reactivates the workspace you used last | Good default; the reference behaviour is unknown | E3-S3 |
| Compose stack written but not run | Docker isn't installed here; CI validates the file | E0-S4 |

## Delivered
- **API:**
  - Auth module: Google plus the dev provider, a signed flow cookie, hashed sessions, CSRF, and error redirects.
  - Workspace module: list, create, join, switch, members and rotate, all under RLS.
  - `internal/app` wiring, shared by `main` and the tests.
- **Contract:** OpenAPI covers 13 paths and 18 schemas; generated TS types and decoders.
- **Worker:**
  - Views `session.current` and `workspace.members`.
  - Five actions: logout, create, join, switch, rotateInvite.
  - The worker validates input and resets data on tenant changes.
- **Web:**
  - Login, onboarding and settings pages.
  - Session guards, the workspace switcher, and a user menu with sign-out.
  - ui-kit gained `Select`, `LinkButton` and `buttonClass`.
- **Local stack:** Compose file plus Caddyfile with CSP. CI e2e now runs against Postgres.
- **Skills extracted:** `add-api-endpoint`, `add-worker-action`, `write-e2e-test`.

## Verification (run locally)
- **Unit tests:** 161 Vitest tests pass. These include the whole session lifecycle through the real kernel, and the guard, onboarding and settings flows through the inline backend and memory router.
- **Go tests:** all pass with `-race` against Postgres 17, at 84.5% statement coverage. They cover the full HTTP flow (sign-in, CSRF, 422, invite, rotate, switch, logout), the login failure kinds, and Google OIDC against a fake issuer.
- **E2E:** 9 Playwright tests pass against the real API and database, with main-thread network forbidden. They cover:
  - first sign-in, then onboarding, then home
  - a deep-link `returnTo`
  - two people joining through the invite code, and rotation
  - switching workspaces and signing out
  - cancelling sign-in
  - axe on the login, onboarding, settings and design pages
