# 2026-09-30 · Sprint 2: tasks

## What the requester asked
> "starts with sprint 2"

## Decisions made during implementation (the requester can override)

| Decision | Why | Recorded in |
|---|---|---|
| Permissions: the creator or task owners manage the task; only the creator manages owners; workspace owners get **no** extra task rights | Matches the reference; admin rights are a one-line change if wanted | ADR-0020 |
| `PATCH /tasks/{id}` requires `If-Match` (428 if missing, 409 if stale); `PUT` set replacements are last-write-wins | Safe concurrent edits without locking | ADR-0020, OpenAPI |
| Client and subtask fields deferred to Sprint 3 | They arrive with their tickets (E8-S1, E4-S6) | backlog |
| E8-S2 (labels) pulled in from Sprint 3 | The task form needs labels | backlog |
| Only workspace owners can delete labels | Deleting affects everyone | ADR-0020 |
| Members and labels queries use stale-while-revalidate (`ttl: 0`) | A new teammate didn't appear in the assignee list for 60 s; found by e2e | domain queries |
| Filter controls are uncontrolled and keyed to the URL; `useView(…, { keepPrevious })` | A controlled checkbox flickered because react-router commits navigation a tick later; found by e2e | skill `add-worker-view` |
| Shared `apperr` package (Go) for 404/403/409/422/428 | Every module answers errors the same way | skill `add-api-endpoint` |
| Generated files are exempt from the 500-line cap | `generated.ts` is generator output | rule `file-size` |

## Delivered
- **API:**
  - The tasks module: list with filters, CRUD, If-Match, and assignees/owners/labels.
  - The permission policy, with a table-driven test.
  - The labels module.
  - Migration 0003 with RLS.
  - `apperr`, `uuidx` and `Optional[T]`.
- **Worker:**
  - Views: `tasks.list` (grouping, due-date tones, filters), `tasks.detail`, `tasks.formOptions`, `labels.list`.
  - Actions: `tasks.create`, `tasks.save` (diffs in the worker), `tasks.delete`, `tasks.refresh`, `labels.create`, `labels.delete`.
- **Web:**
  - The Tasks page, with URL-driven filters and `?task=` / `?create=1` drawers.
  - The task form: people and label pickers, and owners for the creator.
  - A read-only mode for people who can't manage, the unsaved-changes guard, 409 recovery, and delete confirmation.
  - A Labels section in Settings.
- **ui-kit:** `Drawer`, `ConfirmDialog` (native `<dialog>`), `LabelChip`, and 27 palette tokens with contrast tests.

## Verification (run locally)
- **Unit tests:** 228 Vitest tests pass. They include `tasks.save` sending exactly the changed fields with If-Match through the real kernel, the 409 and validation paths, and a 2,000-task view model built in under 100 ms.
- **Go tests:** all pass with `-race` against Postgres 17, at 84% statement coverage across `internal/...`. They include every role against every task action, validation, 428/409, tenant isolation, and deleting a label that tasks use.
- **E2E:** 11 Playwright tests pass. They include create, filter, edit and delete; the assignee's read-only view; an owner gaining edit rights; a **real two-browser 409 conflict** recovered with "Reload latest"; and axe on the task list and drawer.
