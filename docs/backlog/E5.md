# E5 Permissions and change requests

> Mirrors docs/mvp-plan.md §8. Global Definition of Done: docs/definition-of-done.md. Format: ID · Title · Priority · Complexity · Deps.

- **E5-S1 · Task policy engine** · P0 · M · Deps: E4-S1
  - **Status:** Done (Sprints 2–3). `tasksvc.Evaluate`/`Authorize` with a table-driven test covering every role and action. ADR-0021: workspace owners manage every task, including its owners.
  - AC: a table-driven test covers the creator, owner, assignee and viewer roles against every mutation.
- **E5-S2 · Change-request API** · P0 · L · Deps: E5-S1
  - **Status:** Done (Sprint 4, ADR-0023). `POST /tasks/{id}/requests`; decisions at `/requests/{id}/{approve,reject,cancel}` (ServeMux). Flat payload validated per kind; approval applies the change through the same `*Tx` functions as direct edits, in one transaction. "Stale" = the request's precondition no longer holds (field changed since, item gone, already assigned) → 409 `request_stale`. Duplicate pending → 409. `ATTACHMENT_ADD` deferred (needs staged uploads). History events `REQUEST_*`.
  - Endpoints: `POST /tasks/:id/requests` and `POST /tasks/requests/:rid/{approve,reject,cancel}`.
  - Behavior: the payload is typed per kind; approving applies the change through the domain command.
  - AC:
    - Only managers can approve or reject; only the requester can cancel.
    - Approving a stale request gives 409.
    - History events are written.
- **E5-S3 · Request mode UI** · P0 · L · Deps: E5-S2, E4-S4
  - **Status:** Done (Sprint 4). `mode: manage|request|view`; `RequestForm` (status, dates, assignees) with "Awaiting approval: …" hints; the note dialog (≤ 1000); the worker files one request per changed field/assignee (`requests.submit`); checklist toggle/add/remove, subtask and attachment removal file single requests; `RequestsSection` with approve / reject (note) / withdraw.
  - Description: the VM exposes `editMode: manage|request|view` and per-field pending markers; the request dialog takes a note of at most 1000 chars; approve, reject and withdraw actions.
  - AC: the UI matches the reference behavior; each changed field produces one request.
