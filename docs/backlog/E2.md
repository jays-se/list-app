# E2 Backend platform

> Mirrors docs/mvp-plan.md §8. Global Definition of Done: docs/definition-of-done.md. Format: ID · Title · Priority · Complexity · Deps.

- **E2-S1 · Service skeleton** · P0 · M · Deps: ADR-0003
  - **Status:** Done, except OpenTelemetry, which is deferred to E12-S1. Module layout, env config, slog JSON logs, request IDs, recover, security headers, `/healthz`, `/readyz` (DB ping), graceful shutdown, Dockerfile (not built locally: no Docker).
  - Description: module layout, config, structured logging, request id, `/healthz` and `/readyz`, graceful shutdown, OTel.
  - AC: the container image runs; health checks pass.
- **E2-S2 · Contract-first API** · P0 · M · Deps: E2-S1
  - **Status:** Done (Sprint 1). OpenAPI covers auth and workspaces, the TS codegen has a `--check`, the route↔spec test covers both providers, and oasdiff runs in CI. **Changed:** Go stubs are hand-written, not generated (ADR-0018).
  - Description: `api/openapi.yaml` v0, server stub generation, TS types generation, problem+json error middleware.
  - AC: CI fails on a breaking change; every error returns `application/problem+json`.
- **E2-S3 · DB and migrations** · P0 · M · Deps: E2-S1
  - **Status:** Done. Migration 0001 (users, workspaces, memberships, sessions), an in-house migrator (advisory lock, up/down/status), `db.WithTenant`/`WithUser` with RLS, tests run against real Postgres 17 (up/down/up, tenant isolation), `add-db-migration` skill. **Changed:** the schema is incremental; feature tables come with their tickets rather than all at once.
  - Description: the Postgres schema in §3, a migration tool, a seed script, and a tenant-scoped repository base.
  - AC: migrations are up/down tested; every query is scoped by `workspace_id` (enforced by a test).
  - Tasks: extract the `add-db-migration` skill.
- **E2-S4 · Outbox and dispatcher** · P1 · M · Deps: E2-S3
  - **Status:** Done (Sprint 4, ADR-0023). `internal/outbox`: `Emit` in the change's transaction; `Dispatcher` claims rows with `FOR UPDATE SKIP LOCKED`, runs the handler in a savepoint, backs off 2^n s (≤ 1 h), gives up after 10 attempts. Idempotency comes from notification `dedupe_key`s.
  - AC: an event is written in the same transaction; the dispatcher is idempotent; retries use backoff.
- **E2-S5 · Object storage and uploads** · P1 · M · Deps: E2-S3
  - **Status:** Done (Sprint 3). `blobstore` with a local driver (signed `/api/v1/blobs/{token}`) and an S3 driver (in-house SigV4, matching the AWS known-answer test) (ADR-0022). **Not verified:** the S3 driver against a real server (the MinIO download failed twice here; `TestS3RoundTrip` is gated on `TEST_S3_ENDPOINT`). **Deferred:** cleanup of stale PENDING rows (E12).
  - Description: `POST /uploads` returns a presigned PUT; a confirm step checks size and MIME; downloads use a signed GET.
  - AC: limits of 5×5 MB per task and 20 MB per doc are enforced server-side.
