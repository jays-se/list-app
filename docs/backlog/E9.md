# E9 Notifications (in-app)

> Mirrors docs/mvp-plan.md §8. Global Definition of Done: docs/definition-of-done.md. Format: ID · Title · Priority · Complexity · Deps.

- **E9-S1 · Notification generation** · P1 · M · Deps: E2-S4, E4-S8, E5-S2
  - Description: MENTION, ASSIGNED, STATUS, REQUEST and REVIEWED come from outbox consumers; DUE comes from a daily scheduler.
  - AC: users don't get notified of their own actions; per-kind settings are respected.
  - **Status:** Done (Sprint 4). Outbox consumers in `notificationsvc`; recipients per ADR-0023; the DUE scheduler runs hourly (tasks due tomorrow, UTC; one per task per day). Only current members are notified.
- **E9-S2 · Inbox UI** · P1 · M · Deps: E9-S1
  - Description: all/unread filter, mark one or all read, 20 s polling, unread badge, deep link to the task.
  - AC: a notification for a deleted task shows a graceful message.
  - **Status:** Done (Sprint 4). `/inbox?filter=unread`, optimistic mark read / read all, nav badge (`inbox.badge`, "99+"), deep link to `/tasks?task=…`; a deleted task shows "This task was deleted" with the old title.
- **E9-S3 · Notification settings** · P1 · S · Deps: E9-S1
  - **Status:** Done (Sprint 4). Per-user, per-kind in-app switches on the inbox page (optimistic). Per-kind *push* switches arrive with Web Push (E13).
