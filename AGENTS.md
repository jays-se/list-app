## Architecture in one screen

```
React (apps/web) ── render only ──► @app/bridge (useView/useAction) ──postMessage──► Dedicated Worker
                                                                               ├─ @app/worker   kernel + ViewRegistry
                                                                               ├─ @app/domain   queries, actions, view models, validators
                                                                               ├─ @app/query    in-house cache/dedupe/poll/retry/mutations
                                                                               └─ @app/api-client  fetch → /api/v1 (cookie session)
apps/api (Go modular monolith, contract-first api/openapi.yaml) → PostgreSQL, object storage, outbox
```

## Hard rules

1. **React renders only.** Code in `apps/web` must not:
   - call `fetch`, `XMLHttpRequest`, `WebSocket`, or `EventSource`;
   - import `@app/query`, `@app/api-client`, or `@app/domain`;
   - filter, sort, aggregate, or reshape server data.

   It may hold ephemeral UI state (open/closed, focus, uncommitted input drafts). Everything else comes from a worker view model via `useView`, and every change goes through `useAction`. See ADR-0005.
2. **Routing uses `react-router`** (data router). Filter state lives in URL search params. Loaders may only call `bridge.prefetch(...)`. See ADR-0004.
3. **No TanStack Query and no new runtime dependencies without an ADR.** Runtime dependencies are limited to `react`, `react-dom`, and `react-router`. See ADR-0006 and ADR-0012.
4. **Heavy work runs in the worker.** This includes parsing, markdown rendering, aggregation, calendar and grid building, diffing, and file reading and upload.
5. **Main↔Worker messages** are typed `command | rpc | push` in `@app/protocol`. No functions cross the boundary. See ADR-0007.
6. **Permissions are server-computed.** The UI reflects `viewer` flags and never decides access itself.
7. **Contract first.** Change `api/openapi.yaml` before changing API or client code. CI rejects breaking diffs.
8. **File size.** No component or module file may exceed 500 lines; split into a folder instead.
9. **TypeScript strict** for all frontend packages. Go for `apps/api` (ADR-0003, `.agents/rules/backend-go.md`).
10. **Design system.** Every UI piece is built from `@app/ui-kit` and alias tokens (ADR-0014). The system follows Fluent 2 principles, and no `@fluentui/*` package may be imported. Hard-coded colours, spacing and shadows are not allowed.
11. **No cloud-provider services** during the MVP. Everything must run from `docker compose` (ADR-0013). Storage goes through the S3 API only.

## Agentic workflow for every ticket

1. **Understand.** Read the ticket in `docs/backlog/`, its acceptance criteria, and its dependencies.
2. **Inspect.** Read the existing code and ADRs, and reuse what already exists.
3. **Decide.** If the change adds a dependency, changes a boundary, a protocol, or a data model, or reverses an earlier decision, write or update an ADR first.
4. **Plan.** Break the ticket into tasks and note them in the PR description.
5. **Implement** in small increments on `feat/<ticket-id>-<slug>`.
6. **Test** each increment. Follow `docs/testing.md`.
7. **Review against the acceptance criteria** and `docs/definition-of-done.md`.
8. **Document.** Update `docs/`, the ADRs, and the backlog status. If scope or decisions changed in conversation, add a dated entry to `docs/conversation/` **and a row to the overview table in `docs/conversation/README.md`**.
9. **Keep it traceable.** Commit messages and PRs cite the ticket ID. ADRs link to their tickets.

## Commands

| Command | Purpose |
|---|---|
| `pnpm i` | install (also enables `.githooks`) |
| `pnpm dev` | web and worker dev server (`/api` → `API_ORIGIN`, default :8080) |
| `cd apps/api && go run ./cmd/api` | API server; `… migrate up|down [N]|status` |
| `pnpm check` | lint, typecheck, boundaries, agents, tokens, unit tests |
| `pnpm test:coverage` | unit tests with the 80% gate |
| `pnpm test:e2e` | Playwright against the real API and DB (needs `E2E_DATABASE_URL`; starts API :18080 and web :5199) |
| `cd apps/api && go test ./...` | API tests (`TEST_DATABASE_URL` enables the Postgres tests) |
| `pnpm gen:api` | regenerate TS types and decoders from `api/openapi.yaml` (ADR-0018) |
| `pnpm tokens` / `pnpm sync:agents` | regenerate tokens.css / agent adapters |
| `pnpm stack:up` / `stack:full` / `stack:down` | Docker Compose: Postgres, MinIO, API with the dev identity provider (`full` adds Caddy serving the build) |
